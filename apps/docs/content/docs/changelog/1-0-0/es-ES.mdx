## Extensión del navegador

La extensión es la primera parte visible del sistema. Vigila los sitios compatibles, instala el bundle correcto de la presence y envía la actividad a Nowly Host sin pedir al usuario que gestione la infraestructura.

- Las presences solo se ejecutan en los sitios compatibles.
- La extensión carga el bundle firmado correcto para la presence.
- La actividad se envía a Discord a través de Nowly Host local.
- El soporte para user scripts está documentado y limitado porque es un permiso sensible.

## Nowly Host

El compañero nativo convierte el estado de una página en un estado real de Discord. Mantiene la capa del navegador simple y da al sistema un punto de paso claro.

- Recibe payloads de presence desde la extensión.
- Los convierte en actualizaciones de Discord Rich Presence.
- Mantiene la conexión con Discord separada de la sesión del navegador.

## Biblioteca y descubrimiento

La biblioteca pública es la superficie del producto que la gente consulta antes de instalar nada.

- Cada presence tiene una página de detalle dedicada.
- Las URLs soportadas, el historial de versiones, las valoraciones y los comentarios están visibles antes de instalar.
- Las estadísticas de instalación ayudan a saber si una presence está activa y mantenida.
- Las páginas de presence muestran suficiente metadato para entender la integración antes de adoptarla.

## Ciclo de vida de las presences

El ciclo de vida es deliberadamente simple y orientado al usuario:

```txt
install -> enable -> update -> disable -> uninstall
```

- La instalación descarga la última release firmada.
- La actualización mantiene el bundle instalado alineado con la release publicada.
- La desactivación detiene la presence sin quitarla de la lista del usuario.
- La desinstalación elimina la presence de la extensión.

## Documentación y onboarding

El primer lanzamiento estable también definió el material de soporte alrededor del producto.

- El onboarding explica la relación entre extensión, Nowly Host y presences.
- La ayuda cubre los fallos comunes en lugar de asumir que el usuario los deduce.
- La documentación explica la estructura de una presence y cómo se publica.

## Flujo de desarrollo

Esta release también marca el momento en que el proyecto se volvió publicable de forma repetible.

```bash
pnpm presence init "Example"
pnpm presence validate
pnpm presence build example
pnpm presence push example
```

- La validación de metadatos ayuda a mantener el catálogo coherente.
- El empaquetado y la firma forman parte del camino de release.
- La CLI da a los contribuidores una forma predecible de crear y publicar presences.

## Por qué importa `1.0.0`

> Es la release en la que el producto se vuelve coherente: la extensión, Nowly Host, la biblioteca, la documentación y la cadena de publicación encajan.
