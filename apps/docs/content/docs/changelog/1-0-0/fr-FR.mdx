## Extension navigateur

L'extension est la première partie visible du système. Elle surveille les sites compatibles, installe le bon paquet de présence et transmet l'activité à Nowly Host sans demander à l'utilisateur de gérer l'infrastructure.

- Les présences ne s'exécutent que sur les sites compatibles.
- L'extension charge le bon paquet signé pour la présence.
- L'activité est transmise à Discord via Nowly Host local.
- La prise en charge des user scripts est documentée et protégée car il s'agit d'une permission sensible.

## Nowly Host

Nowly Host transforme l'état d'une page en statut Discord réel. Il garde la couche navigateur simple et donne au système un point de passage clair.

- Il reçoit les données de présence depuis l'extension.
- Il les convertit en mises à jour Discord Rich Presence.
- Il garde la connexion Discord séparée de la session navigateur.

## Bibliothèque et découverte

La bibliothèque publique est la surface produit que les utilisateurs consultent avant d'installer quoi que ce soit.

- Chaque présence dispose d'une page détail dédiée.
- Les URL prises en charge, l'historique de version, les notes et les commentaires sont visibles avant installation.
- Les statistiques d'installation aident à juger si une présence est active et maintenue.
- Les pages de présence exposent assez de métadonnées pour comprendre l'intégration avant de l'adopter.

## Cycle de vie des présences

Le cycle de vie est volontairement simple et orienté utilisateur :

```txt
install -> enable -> update -> disable -> uninstall
```

- L'installation récupère la dernière version signée.
- La mise à jour aligne le paquet installé avec la version publiée.
- La désactivation stoppe la présence sans la retirer de la liste utilisateur.
- La désinstallation supprime la présence de l'extension.

## Documentation et onboarding

La première version stable a aussi posé les bases des supports autour du produit.

- Le parcours d'onboarding explique la relation entre extension, Nowly Host et présences.
- Le dépannage couvre les cas d'échec courants au lieu de supposer que l'utilisateur les devine.
- La documentation explique la structure d'une présence et sa publication.

## Parcours développeur

Cette version est aussi le moment où le projet est devenu publiable de manière répétable.

```bash
pnpm presence init "Example"
pnpm presence validate
pnpm presence build example
pnpm presence push example
```

- La validation des métadonnées aide à garder le catalogue cohérent.
- Le bundling et la signature font partie du chemin de publication.
- La CLI donne aux contributeurs une manière prévisible de créer et publier des présences.

## Pourquoi `1.0.0` compte

> C'est la version où le produit devient cohérent : l'extension, Nowly Host, la bibliothèque, la documentation et la chaîne de publication s'alignent.
