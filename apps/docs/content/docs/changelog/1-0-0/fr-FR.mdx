## Extension navigateur

L'extension est la première partie visible du système. Elle surveille les sites compatibles, installe le bon bundle de presence et transmet l'activité au service natif sans demander à l'utilisateur de gérer l'infrastructure.

- Les presences ne s'exécutent que sur les sites compatibles.
- L'extension charge le bon bundle signé pour la presence.
- L'activité est transmise à Discord via le service natif local.
- La prise en charge des user scripts est documentée et protégée car il s'agit d'une permission sensible.

## Service natif

Le compagnon natif transforme l'état d'une page en statut Discord réel. Il garde la couche navigateur simple et donne au système un point de passage clair.

- Il reçoit les payloads de presence depuis l'extension.
- Il les convertit en mises à jour Discord Rich Presence.
- Il garde la connexion Discord séparée de la session navigateur.

## Bibliothèque et découverte

La bibliothèque publique est la surface produit que les utilisateurs consultent avant d'installer quoi que ce soit.

- Chaque presence dispose d'une page détail dédiée.
- Les URLs supportées, l'historique de version, les notes et les commentaires sont visibles avant installation.
- Les statistiques d'installation aident à juger si une presence est active et maintenue.
- Les pages de presence exposent assez de métadonnées pour comprendre l'intégration avant de l'adopter.

## Cycle de vie des presences

Le cycle de vie est volontairement simple et orienté utilisateur :

```txt
install -> enable -> update -> disable -> uninstall
```

- L'installation récupère la dernière release signée.
- La mise à jour aligne le bundle installé avec la release publiée.
- La désactivation stoppe la presence sans la retirer de la liste utilisateur.
- La désinstallation supprime la presence de l'extension.

## Documentation et onboarding

La première version stable a aussi posé les bases des supports autour du produit.

- Le parcours d'onboarding explique la relation entre extension, service natif et presences.
- Le dépannage couvre les cas d'échec courants au lieu de supposer que l'utilisateur les devine.
- La documentation explique la structure d'une presence et sa publication.

## Workflow développeur

Cette release est aussi le moment où le projet est devenu publiable de manière répétable.

```bash
pnpm presence init "Example"
pnpm presence validate
pnpm presence build example
pnpm presence push example
```

- La validation des métadonnées aide à garder le catalogue cohérent.
- Le bundling et la signature font partie du chemin de release.
- La CLI donne aux contributeurs une manière prévisible de créer et publier des presences.

## Pourquoi `1.0.0` compte

> C'est la release où le produit devient cohérent : l'extension, le service natif, la bibliothèque, la documentation et la chaîne de publication s'alignent.
