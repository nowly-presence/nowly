## Navegación de la extensión

El badge de actualización ahora envía a la ruta actual de la biblioteca en lugar de la antigua ruta prefijada por idioma. Así la extensión queda alineada con la estructura actual del sitio.

## Estado de actualización

Cuando una presence termina de actualizarse, la versión instalada se refresca inmediatamente. El badge ya no se queda visible hasta reabrir la extensión, así que el estado mostrado coincide con lo que el usuario acaba de hacer.

## Tracking activo

`activeUsers` ahora sigue dispositivos en lugar de guardar un simple flag de presence.

- un `deviceId` estable actúa como clave de tracking
- los heartbeats actualizan el registro activo en vez de solo cambiar un bit
- el sitio puede reflejar por fin un contador real de activos en lugar de un placeholder de "al menos una sesión activa"

## Desactivación

Desactivar una presence ahora elimina el dispositivo del conjunto activo. Al volver a activarla, se añade de nuevo al mismo modelo de tracking, para mantener el contador alineado con el estado runtime real.

## Limpieza al desinstalar

La extensión usa una URL de desinstalación best-effort, y la parte web purga el dispositivo asociado cuando llega la solicitud de cleanup.

- es un flujo de cleanup best-effort, no un script post-uninstall
- el `deviceId` se envía a la ruta de cleanup para que el backend elimine el estado activo asociado
- eso mantiene el comportamiento coherente aunque la extensión ya no exista

## Pulido de la página detalle

Los bloques de icono transparentes ahora descansan sobre un backdrop blur, para que la banner de la presence no se filtre tanto a través del tratamiento del icono. El efecto se aplica al contenedor del icono, no a la banner detrás.

## Estructura del changelog

El changelog ya no es una sola página con anclas. Ahora está dividido en un índice y páginas por versión:

```txt
/docs/changelog
/docs/changelog/1-0-0
/docs/changelog/1-1-0
```

Esa estructura hace que el historial de releases sea más fácil de mantener, enlazar y navegar desde la sidebar.

## Navegación docs

El changelog ahora aparece en la sidebar docs como una categoría dedicada, con cada versión listada como hijo. Las notas de versión siguen el mismo modelo de navegación que el resto de la documentación.

## Indexación docs

El sitemap ahora incluye las páginas del changelog, así que las release notes se tratan como documentación real en lugar de quedar fuera del índice público.

## UI del host

La página host ahora mantiene el flujo de descarga en un solo lugar. Las tarjetas secundarias open source y bajo impacto quedan ocultas por ahora, y el CTA de instalación usa un icono en lugar de una flecha de texto.

El selector de plataforma, la línea de versión y los botones de descarga ahora están agrupados en un panel compacto debajo del hero principal. macOS y Linux ya no heredan texto específico de Windows, y la página ya no muestra un segundo título compitiendo debajo del hero.

## Almacenamiento del host

Los requirements del host ya no anuncian un `~15 MB` fijo. Esa nota no era exacta, así que la página ahora muestra los tamaños exactos del manifest host `1.1.0`:

- instalador Windows: `3,71 MB`
- portable Windows: `1,82 MB`
- archivo macOS: `3,38 MB`
- archivo Linux: `1,76 MB`

## Plataformas del inicio

La sección de plataformas de la página de inicio se reconstruyó alrededor de la lista live de presences, en lugar de un muro de logos demasiado estático. El antiguo texto `Disponibles` se eliminó, y cada servicio ahora usa una tarjeta más completa con su icono, descripción localizada, número de instalaciones, usuarios activos, valoración y enlace directo a la página de detalle de la biblioteca.

El tratamiento visual de las tarjetas también usa un glow de dos capas basado en el color del icono: una capa amplia y suave, y otra más corta cerca de la esquina superior derecha. La sección se siente más actual sin desconectarse de los datos reales de la biblioteca.

## Espaciado de contribuidores

Las filas de contribuidores ahora son de ancho completo y más compactas, lo que elimina el espacio visual raro entre personas en la sección.

## Docs CLI

La nota de build de producción se retiró de la documentación CLI para no dejar a entender que hay que seguir un camino separado de build Chrome Web Store ahí.

## Impacto

```txt
Affected paths:
POST /presences/active
DELETE /presences/active/:deviceId
GET /library/[item]
GET /
GET /docs/changelog
GET /docs/changelog/1-0-0
GET /docs/changelog/1-1-0
```

> Esta release no introduce un workflow nuevo. Hace que el workflow existente sea coherente y medible.
