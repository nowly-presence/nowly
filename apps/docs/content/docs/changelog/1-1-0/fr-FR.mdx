## Navigation de l'extension

Le badge de mise à jour envoie maintenant vers la route courante de la bibliothèque au lieu de l'ancien chemin préfixé par la langue. L'extension reste ainsi alignée avec la structure actuelle du site.

## État de mise à jour

Quand une presence termine sa mise à jour, la version installée est rafraîchie immédiatement. Le badge ne reste plus visible jusqu'à la réouverture de l'extension, donc l'état affiché correspond à ce que l'utilisateur vient de faire.

## Tracking actif

`activeUsers` suit maintenant des appareils au lieu de stocker un simple drapeau de presence.

- un `deviceId` stable sert de clé de tracking
- les heartbeats mettent à jour l'enregistrement actif au lieu de simplement basculer un bit
- le site peut enfin refléter un vrai compteur d'actifs au lieu d'un placeholder du type "au moins une session active"

## Désactivation

Désactiver une presence retire maintenant l'appareil de l'ensemble actif. La réactiver le remet dans le même modèle de tracking, pour garder le compteur aligné avec l'état runtime réel.

## Nettoyage à la désinstallation

L'extension utilise une URL de désinstallation best-effort, et le côté web purge l'appareil associé quand la requête de cleanup arrive.

- c'est un flux de cleanup best-effort, pas un script post-uninstall
- le `deviceId` est transmis à la route de cleanup pour que le backend retire l'état actif associé
- cela garde un comportement cohérent même quand l'extension a déjà disparu

## Polish des pages détail

Les blocs d'icône transparents reposent maintenant sur un backdrop blur, pour que la bannière de la presence ne traverse plus autant le traitement de l'icône. L'effet est appliqué au conteneur de l'icône, pas à la bannière derrière.

## Structure du changelog

Le changelog n'est plus une seule page avec des ancres. Il est maintenant découpé en un index et des pages par version :

```txt
/docs/changelog
/docs/changelog/1-0-0
/docs/changelog/1-1-0
```

Cette structure rend l'historique des releases plus simple à maintenir, à lier et à parcourir depuis la sidebar.

## Navigation docs

Le changelog apparaît maintenant dans la sidebar docs comme une catégorie dédiée, avec chaque version listée en enfant. Les notes de version restent ainsi dans le même modèle de navigation que le reste de la documentation.

## Indexation docs

Le sitemap inclut maintenant les pages du changelog, donc les release notes sont traitées comme de la vraie documentation au lieu d'être laissées hors de l'index public.

## UI du host

La page host garde maintenant le flux de téléchargement au même endroit. Les cartes secondaires open source et faible empreinte sont masquées pour l'instant, et le CTA d'installation utilise une icône au lieu d'une flèche texte.

Le sélecteur de plateforme, la ligne de version et les boutons de téléchargement sont maintenant regroupés dans un panneau compact sous le hero principal. macOS et Linux n'héritent plus d'un texte spécifique à Windows, et la page n'affiche plus un deuxième titre concurrent sous le hero.

## Stockage du host

Les requirements du host n'annoncent plus un `~15 MB` fixe. Cette note n'était pas exacte, donc la page affiche maintenant les tailles exactes du manifest host `1.1.0` :

- installateur Windows : `3,71 Mo`
- portable Windows : `1,82 Mo`
- archive macOS : `3,38 Mo`
- archive Linux : `1,76 Mo`

## Plateformes accueil

La section plateformes de la page d'accueil a été reconstruite autour de la liste live des presences, au lieu d'un mur de logos trop statique. L'ancien libellé `Disponibles` a été retiré, et chaque service utilise maintenant une carte plus complète avec son icône, sa description localisée, le nombre d'installations, les utilisateurs actifs, la note et un lien direct vers la page détail de la bibliothèque.

Le traitement visuel des cartes utilise aussi un glow en deux couches basé sur la couleur de l'icône : une couche large et douce, puis une couche plus courte près du coin supérieur droit. La section paraît plus actuelle sans se déconnecter des vraies données de la bibliothèque.

## Espacement contributeurs

Les lignes de contributeurs sont maintenant pleine largeur et plus serrées, ce qui retire l'écart visuel parasite entre les personnes dans la section.

## Docs CLI

La note de build production a été retirée de la documentation CLI pour ne pas laisser entendre qu'il faut suivre un chemin séparé de build Chrome Web Store à cet endroit.

## Impact

```txt
Affected paths:
POST /presences/active
DELETE /presences/active/:deviceId
GET /library/[item]
GET /
GET /docs/changelog
GET /docs/changelog/1-0-0
GET /docs/changelog/1-1-0
```

> Cette release n'introduit pas un nouveau workflow. Elle rend le workflow existant cohérent et mesurable.
