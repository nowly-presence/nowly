<CalloutWarning>
Les scripts de présence dans les iFrames **ne sont pas encore implémentés** dans le runtime de l'extension Nowly. `presence.on("iFrameData")` est réservé dans les types SDK, mais l'extension n'injecte pas dans les cadres imbriqués et n'émet pas cet événement. Préférez la page de niveau supérieur (DOM, `<audio>` / `<video>`, état public) jusqu'à la livraison de cette fonctionnalité.
</CalloutWarning>

## Quand les iFrames comptent

Certains sites affichent des lecteurs multimédias ou un état important dans des iframes. Un script de présence normal peut ne pas pouvoir tout lire depuis la page de niveau supérieur.

Tant que le support iframe n'existe pas, évitez les sites dont l'activité n'est exposée que dans un cadre cross-origin, ou documentez la limite dans la description de la présence.

## API prévue

L'API Presence réserve un événement `iFrameData` pour une communication future au niveau du cadre&nbsp;:

```ts filename="presence.ts"
presence.on("iFrameData", async (...args) => {
  presence.info("Données iframe reçues")
})
```

Ne vous appuyez pas sur ce listener dans une présence en production aujourd'hui.

## Approche recommandée

Utilisez la gestion des iframes uniquement lorsque la page principale ne peut pas accéder à l'état requis.

Préférez les sélecteurs DOM stables, les éléments multimédias et l'état public de la page avant d'ajouter de la logique iframe.

## Sécurité

Évitez de collecter des données personnelles ou sensibles depuis les cadres. Une présence ne doit envoyer que des informations d'activité utiles pour Discord Rich Presence.
