title: Proxy de imágenes
description: Usa el proxy de imágenes de Nowly cuando Discord no pueda cargar directamente una imagen de presencia desde un CDN externo compatible.
---

## Para qué sirve

El proxy de imágenes está pensado para un caso concreto: una presencia puede ver una imagen pública en la página, pero Discord no puede cargarla de forma fiable desde la URL original.

Es útil para miniaturas de vídeo, avatares, posters o imágenes de categoría servidas por un CDN externo cuando:

- la imagen es pública y ya está visible en el navegador;
- la URL del CDN es demasiado larga para Discord Rich Presence;
- Discord rechaza, deja expirar o no puede descargar la imagen directa;
- la presencia necesita mostrar una imagen del contenido en lugar de usar solo el logo del servicio.

No es un proxy de imágenes genérico. La API solo acepta servicios y dominios permitidos explícitamente.

## Cómo funciona

El flujo recomendado usa una URL corta temporal:

```txt
POST https://api.nowly.me/images-proxy
GET  https://api.nowly.me/images-proxy/<id>
```

La presencia envía a la API la URL CDN real de la imagen. La API comprueba que el servicio esté permitido, descarga la imagen, valida su tipo MIME y su tamaño, y la guarda temporalmente en caché. Después devuelve una URL corta como:

```txt
https://api.nowly.me/images-proxy/abc123...
```

Esa URL devuelve directamente los bytes de la imagen con el `Content-Type` correcto. Está pensada para `largeImageKey` o `smallImageKey`.

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const image = await createCachedImageProxyUrl("tiktok", imageUrl)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: image ?? Assets.Logo,
})
```

La caché es corta, actualmente cinco minutos. El helper también mantiene una caché en memoria dentro de la presencia para no llamar a la API en cada actualización.

## Endpoint directo

El proxy directo anterior sigue disponible para pruebas manuales o URLs que ya sean suficientemente cortas:

```txt
https://api.nowly.me/image-proxy?service=<service>&url=<url-codificada>
https://api.nowly.me/i?u=<url-codificada>
```

Los parámetros `url` y `u` deben codificarse con `encodeURIComponent`. Para Discord Rich Presence, prefiere `createCachedImageProxyUrl`, porque Discord limita las claves de imagen a 300 caracteres.

## Configuración en una presencia

Primero, extrae la URL real de la imagen desde la página:

```ts filename="presence.ts"
const getPoster = (video: HTMLVideoElement): string | undefined => {
  if (video.poster) return video.poster

  const image = video.closest("[data-video]")?.querySelector("img")
  return image?.getAttribute("src") ?? undefined
}
```

Después, pasa esa URL por el helper antes de definir la actividad:

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const poster = await createCachedImageProxyUrl("tiktok", getPoster(video))

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: poster ?? Assets.Logo,
})
```

Mantén siempre un asset de respaldo. Si la página no tiene imagen, la imagen es demasiado pesada o el origen no está permitido, la presencia debe seguir funcionando con `Assets.Logo` o un asset local.

## Añadir un servicio

Los dominios permitidos se validan en la API, no en la presencia. Para añadir un servicio nuevo, agrega una entrada de configuración del proxy con:

- un `id` de servicio estable;
- los sufijos de host CDN permitidos;
- las cabeceras que requiera el CDN;
- un límite claro sobre lo que la presencia puede enviar al proxy.

Si una presencia necesita un nuevo dominio de imagen, puedes usar el helper en tu PR de presencia y explicar:

- qué hostnames exactos necesitan soporte;
- por qué Discord no puede usar la URL directa;
- qué imagen verá el usuario;
- por qué la imagen es pública y se puede proxificar de forma segura.

Los reviewers decidirán si añaden esas URLs a los servicios compatibles. Pueden rechazar orígenes demasiado amplios, inestables, privados o inseguros.

## Límites y seguridad

El proxy solo debe servir imágenes públicas necesarias para presencias revisadas y aceptadas. Rechaza URLs que no sean HTTPS, dominios no permitidos, respuestas que no sean imágenes y archivos demasiado grandes.

No lo uses para contenido de cuentas privadas, recursos autenticados, URLs de tracking, entradas arbitrarias del usuario o contenido que no sea una imagen.
