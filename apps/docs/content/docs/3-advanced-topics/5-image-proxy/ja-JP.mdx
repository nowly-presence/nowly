---
title: 画像プロキシ
description: Discordが対応する外部CDNの画像を直接読み込めない場合に、Nowlyの画像プロキシを使用します。
---

## 用途

画像プロキシは、プレゼンスからページ上の公開画像を参照できても、Discordが元のURLから安定して読み込めない場合のためのものです。

外部CDNが提供する動画のサムネイル、アバター、ポスター、カテゴリー画像について、次のような場合に役立ちます。

- 画像が公開されており、ブラウザー上でも表示されている。
- CDNのURLがDiscord Rich Presenceには長すぎる。
- Discordが直接の画像URLを拒否する、URLの有効期限が切れる、またはダウンロードできない。
- サービスのロゴではなく、コンテンツに応じた画像を表示したい。

汎用的な画像プロキシではありません。APIは明示的に許可されたサービスとドメインのみを受け付けます。

## 仕組み

推奨される方法は、一時的な短縮URLを使うことです。

```txt
POST https://api.nowly.me/images-proxy
GET  https://api.nowly.me/images-proxy/<id>
```

プレゼンスはCDN上の実際の画像URLをAPIに送ります。APIはサービスの対応状況を確認して画像を取得し、MIMEタイプとサイズを検証して一時的にキャッシュします。次のような短縮URLを返します。

```txt
https://api.nowly.me/images-proxy/abc123...
```

このURLは、正しい`Content-Type`を付けて画像データを直接返します。`largeImageKey`または`smallImageKey`での使用を想定しています。

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const image = await createCachedImageProxyUrl("tiktok", imageUrl)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: image ?? Assets.Logo,
})
```

キャッシュの有効期間は短く、現在は5分です。ヘルパーはプレゼンス内のメモリーにもキャッシュを保持し、更新のたびにAPIを呼ばないようにします。

## 直接アクセス用エンドポイント

従来の直接プロキシは、手動テストや、元から十分に短いURL向けに引き続き利用できます。

```txt
https://api.nowly.me/image-proxy?service=<service>&url=<encoded-url>
https://api.nowly.me/i?u=<encoded-url>
```

`url`と`u`の値は`encodeURIComponent`でエンコードしてください。Discordでは画像キーが300文字に制限されるため、Rich Presenceには`createCachedImageProxyUrl`を推奨します。

## プレゼンスでの設定

まずページから実際の画像URLを取得します。

```ts filename="presence.ts"
const getPoster = (video: HTMLVideoElement): string | undefined => {
  if (video.poster) return video.poster

  const image = video.closest("[data-video]")?.querySelector("img")
  return image?.getAttribute("src") ?? undefined
}
```

アクティビティを設定する前に、取得したURLをヘルパーに渡します。

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const poster = await createCachedImageProxyUrl("tiktok", getPoster(video))

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: poster ?? Assets.Logo,
})
```

代替画像は必ず用意してください。ページに画像がない場合、画像が大きすぎる場合、または取得元が許可されていない場合も、`Assets.Logo`やローカルの画像でプレゼンスを動作させます。

## サービスの追加

許可されたドメインはプレゼンスではなくAPIが検証します。実行時にリクエストするだけで任意のドメインをプロキシできるわけではありません。独立した承認手順やAPIコードの変更は不要です。プレゼンスで必要なホストを、そのプレゼンス自身の`metadata.json`に宣言してください。ヘルパーに渡す`service`と同じ値（プレゼンスのslug）を使います。

```json filename="metadata.json"
"imageProxy": {
  "hostSuffixes": ["netflix.com", "nflxvideo.net", "nflximg.net"],
  "headers": { "Referer": "https://www.netflix.com/" }
}
```

この宣言は、`metadata.json`のほかの情報と同様に自動的にAPIへ公開されます。APIは、そのプレゼンス自身の`service` IDについてのみ宣言を信頼します。別のプレゼンスのホストを代理で宣言することはできず、対象URLのホスト名が宣言された接尾辞のいずれかに実際に一致する場合のみリクエストが許可されます。

PRで`imageProxy`を変更すると、プレゼンスのプレビューボットが自動的に検出し、宣言したホスト名を列挙する**Image Proxy Requested**セクションをコメントに追加して、`image-proxy`ラベルを付けます。マージ前には、レビュー担当者がホストが公開されておりプロキシに適しているか確認する必要があります。Discordが直接URLを使えない理由と、ユーザーに表示される画像をPRで説明してください。

## 制限とセキュリティ

プロキシが配信するのは、レビュー済みのプレゼンスが宣言したホストの公開画像だけです。HTTPS以外のURL、宣言された接尾辞に一致しないホスト、画像以外の応答、大きすぎるファイルは拒否されます。

エンドポイントは公開されており、認証はありません（プレゼンスがブラウザーから直接呼び出すため、添付するシークレットはありません）。API全体のレート制限を共有し、プレゼンスごとの割り当てはありません。非公開のアカウント情報、認証が必要なリソース、追跡用URL、任意のユーザー入力、画像以外のコンテンツには使わないでください。
