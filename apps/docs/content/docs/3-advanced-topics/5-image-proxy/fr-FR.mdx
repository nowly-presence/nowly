title: Proxy d'image
description: Utilisez le proxy d'image Nowly lorsque Discord ne peut pas charger directement une image de présence depuis un CDN externe pris en charge.
---

## À quoi ça sert

Le proxy d'image est prévu pour un cas précis : une présence peut voir une image publique dans la page, mais Discord ne parvient pas à la charger correctement depuis l'URL d'origine.

C'est typiquement utile pour des miniatures de vidéos, des avatars, des posters ou des images de catégorie servies par un CDN externe lorsque :

- l'image est publique et déjà visible dans le navigateur ;
- l'URL CDN est trop longue pour Discord Rich Presence ;
- Discord refuse, laisse expirer ou ne télécharge pas correctement l'image directe ;
- la présence doit afficher une image liée au contenu plutôt que seulement le logo du service.

Ce n'est pas un proxy d'image générique. L'API accepte uniquement les services et les domaines explicitement autorisés.

## Fonctionnement

Le flux recommandé passe par une URL courte temporaire :

```txt
POST https://api.nowly.me/images-proxy
GET  https://api.nowly.me/images-proxy/<id>
```

La présence envoie à l'API l'URL CDN réelle de l'image. L'API vérifie que le service est pris en charge, télécharge l'image, valide son type MIME et sa taille, puis la stocke temporairement en cache. Elle renvoie ensuite une URL courte du type :

```txt
https://api.nowly.me/images-proxy/abc123...
```

Cette URL renvoie directement les bytes de l'image avec le bon `Content-Type`. Elle est conçue pour être utilisée dans `largeImageKey` ou `smallImageKey`.

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const image = await createCachedImageProxyUrl("tiktok", imageUrl)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: image ?? Assets.Logo,
})
```

Le cache est court, actuellement cinq minutes. Le helper garde aussi un cache mémoire côté présence pour éviter de rappeler l'API à chaque update.

## Endpoint direct

L'ancien proxy direct reste disponible pour les tests manuels ou les URLs déjà assez courtes :

```txt
https://api.nowly.me/image-proxy?service=<service>&url=<url-encodée>
https://api.nowly.me/i?u=<url-encodée>
```

Les paramètres `url` et `u` doivent être encodés avec `encodeURIComponent`. Pour Discord Rich Presence, préférez `createCachedImageProxyUrl`, car Discord limite les clés d'image à 300 caractères.

## Mise en place dans une présence

Récupérez d'abord l'URL réelle de l'image depuis la page :

```ts filename="presence.ts"
const getPoster = (video: HTMLVideoElement): string | undefined => {
  if (video.poster) return video.poster

  const image = video.closest("[data-video]")?.querySelector("img")
  return image?.getAttribute("src") ?? undefined
}
```

Envoyez ensuite cette URL au helper avant de définir l'activité :

```ts filename="presence.ts"
import { createCachedImageProxyUrl } from "@nowly/sdk"

const poster = await createCachedImageProxyUrl("tiktok", getPoster(video))

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: poster ?? Assets.Logo,
})
```

Gardez toujours un asset de secours. Si la page ne fournit aucune image, si l'image est trop lourde ou si l'origine n'est pas autorisée, la présence doit continuer à fonctionner avec `Assets.Logo` ou un asset local.

## Ajouter un service

Les domaines autorisés sont vérifiés côté API, pas côté présence. Pour ajouter un nouveau service, il faut ajouter une entrée de configuration côté proxy avec :

- un `id` de service stable ;
- les suffixes de domaines CDN autorisés ;
- les en-têtes nécessaires, si le CDN en exige ;
- une limite claire sur ce que la présence peut envoyer au proxy.

Si une présence a besoin d'un nouveau domaine d'image, vous pouvez utiliser le helper dans votre PR et expliquer :

- les hostnames exacts à prendre en charge ;
- pourquoi Discord ne peut pas utiliser l'URL directe ;
- quelle image sera affichée à l'utilisateur ;
- pourquoi cette image est publique et peut être proxifiée sans risque.

Les reviewers décideront ensuite s'ils acceptent d'ajouter ces URLs aux services pris en charge. Ils peuvent refuser les origines trop larges, instables, privées ou dangereuses.

## Limites et sécurité

Le proxy ne doit servir que des images publiques nécessaires à des présences relues et acceptées. Il refuse les URLs non HTTPS, les domaines non autorisés, les réponses qui ne sont pas des images et les fichiers trop lourds.

Ne l'utilisez pas pour des comptes privés, des ressources authentifiées, des URLs de tracking, des entrées utilisateur arbitraires ou du contenu qui n'est pas une image.
